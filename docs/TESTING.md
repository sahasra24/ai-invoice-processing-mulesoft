## 2. Written but NOT executed in the build environment

The build machine had no Mule runtime, no Anypoint Studio and no MySQL. These items are complete and follow documented Mule 4 syntax, but they have **not** been run:

| Item | Expected verification step |
|---|---|
| Deployment of the three Mule apps | Import into Studio 7.21+, then Run (see DEVELOPMENT-GUIDE A6) |
| 36 MUnit tests (System 12, Process 15, Experience 9) | *Run MUnit* in Studio (bundles the Mule EE runtime). `mvn test` from the command line also works, but only with MuleSoft EE repository credentials in `~/.m2/settings.xml`: the runtime artifact `com.mulesoft.mule.distributions:mule-runtime-impl-no-services-bom` returns HTTP 401 without them, which is why the tests could not run in the build environment |
| 4 DB integration MUnit tests | `mvn test -Dmunit.tags=integration` against MySQL |
| SQL scripts on a real MySQL 8 server | `mysql < database/01-schema.sql` |
| Postman end-to-end run (49 requests) | Collection Runner, folders 00 to 06 |
| Claude integration (`AI_PROVIDER=claude`) | Requires an Anthropic API key. Request and response mapping is unit-tested; the live call is not |
| CloudHub 2.0 deployment | Requires an Anypoint account |

**Most likely first-run fixes, if any:**
- Child-element ordering inside connector configs. Studio fixes this when you open and save the component.
- Small expression typing differences between the DataWeave CLI and the Mule runtime.

Please report anything you hit. TROUBLESHOOTING.md lists the known cases.
